# 日々

個人の日記サイト。

## 使い方

```sh
npm run build   # site/ に生成
npm run dev     # 監視ビルド＋ http://localhost:8888 で確認（PORT で変更可）
npm run new     # 今の日付・時刻のファイルを content/ に作る
npm run ref     # 記法のデモページをブラウザで開く
```

`npm run dev` は `content/`・`assets/`・`site.config.json` の変更を監視して自動で再ビルドする。

生成物は `site/` に入る。そのまま任意の静的ホスティングに置ける。

## 書き方

時刻ブロックごとに一ファイル。パスが日付と時刻になる。

```
content/2026/08/30/10-40.md       ← 2026-08-30 の 10:40 の記述
content/2026/08/30/19-20.md       ← 同じ日の 19:20 の記述
```

写真は `content/` には置かず R2 にある（[写真の置き場](#写真の置き場)）。

ファイルの中身は本文だけ。時刻はファイル名（`HH-MM.md`）から取る。

`npm run new`（`scripts/new.mjs`）はこのパスのファイルを実行時の日付・時刻で作る。後ろに文章を書くとそれが本文になる。

```sh
npm run new                    # content/2026/08/30/10-40.md を空で作る
npm run new "梅雨明け。"       # 同じファイルを本文入りで作る
```

同じ分のファイルがすでにあるときは、空行を挟んで後ろに足す。

日付と時刻は手で指定できる。書き忘れた日を後から足すとき用。

```sh
npm run new -- -d 2026-08-29 -t 21:30 "昨日のこと。"
```

- `-d` / `--date` — `YYYY-MM-DD`
- `-t` / `--time` — `HH:MM`（`HH-MM` でも可）
- `--` — これより後ろはすべて本文。本文が `-` で始まるときに使う

`npm run` 経由でオプションを渡すときは、`npm run new -- ...` のように `--` を挟む。

```
段落。空行で区切る。

段落の続き。

![キャプション](https://img.example.com/img/2026-08-30-10-41-05.jpg)
```

- `[表示文字](URL)` — 文中のリンク。段落・引用・箇条書き・追記の中で使える。対応するインライン記法はこれだけで、強調やインラインコードはない
- `![キャプション](URL)` — 写真。書く画面から入れると R2 の URL がここに入る。書いた位置に、一枚につき一つの図として出る。日ディレクトリからの相対パス（`img/xxx.jpg`）で手元のファイルを指すこともできる
- `> 引用文` — 引用。最後の行を `> -- 出典` にすると出典が付く
- `- 項目` — 箇条書き
- `@追記 09.02` — 追記。続く行がその段落になる。日付は省略できて、`@追記 本文` と続けて書けばその行がそのまま追記の一段落目になる
- `@link URL` — リンクカード。タイトル・説明・サイト名・サムネイルはビルド時に OGP から自動取得し、`.cache/linkcard.json` にキャッシュする（二回目以降はネットワークに出ない）。`@link URL | タイトル | 説明 | サイト名 | サムネイル` と手書きすれば取得値より優先。取得に失敗したときは警告を出して URL だけのカードになる
- `@youtube 動画ID | キャプション` — YouTube 埋め込み
- `@x リンク | キャプション` — X（旧 Twitter）埋め込み。`@twitter` も同じ。ポストの URL をそのまま書けばよい（ID だけでもよい）。読み込めたときは X の埋め込み iframe が出るが、それとは別にビルド時に oEmbed で本文・ハンドル・日付を取り、`.cache/xpost.json` に貯めてカードとして HTML に書き出す。JS を切っている・X に繋がらない・ポストが消えた、のいずれでもこのカードが残る。画像と動画は oEmbed に入ってこないので、カード側は注記だけになる
- `@map 場所 | リンク` — その時刻ブロックの場所。本文の中には出ず、時刻の行の右端（`11:00 ─── 場所`）に付く。ファイルのどこに書いてもよいが、一つの時刻に一つだけ（二つ以上あるとビルドが止まる）。地図は埋め込まず、リンクは Google マップや Apple マップの共有リンクなど何でもよく、省けば名前だけになる
- `@music 共有リンク | キャプション` — Apple Music 埋め込み。`https://music.apple.com/...` の共有リンクをそのまま書けば埋め込み用 URL に変換される。曲（`?i=` 付き）は小さい枠、アルバム・プレイリストは背の高い枠になる（`| tall` で強制も可）

記法を一通り並べたデモページがある。`npm run ref` で一時ディレクトリにビルドしてブラウザで開くので、`ref/` の md と実際の見た目を見比べられる。`content/` と `site/` には触らないから、記法を試す場所としても使える（`ref/` を編集すると作り直す）。ポートは 8899、`PORT` で変えられる。

写真には `width`/`height`/`aspect-ratio` を必ず出すので、読み込み中もレイアウトがずれない。寸法は、R2 の写真なら入れたときに測ってあり（[写真の置き場](#写真の置き場)）、それ以外の外部 URL ならビルド時に一度落として測って `.cache/imagesize.json` に貯める。

手元に置いた写真（JPEG か PNG）も動く。日ディレクトリの下なら `img/` でも直下でもよく、ビルド時に日ページの隣（`/2026/08/30/img/10-41.jpg`）へディレクトリの形のままコピーされ、寸法はそのファイルから読む。ただしこれは Static Assets のファイル数を使うので、常用するなら R2 のほうに置く。

## 書く画面

`npm run dev` の確認サーバに、ブラウザで書く画面が乗っている。

```
http://localhost:8888/_write
```

左が今までの記事、真ん中が本文、右がプレビュー。
プレビューは実際に生成した日ページで、保存すると再ビルドの完了を待ってから返すので、保存した瞬間に新しくなる。

上のバーの日付と時刻が、そのまま書き込み先（`content/YYYY/MM/DD/HH-MM.md`）になる。

- **いま** — 実行時の日付・時刻にする。**新規** — そこから空の状態で始める
- 日付・時刻を変えても書きかけの文章は消えない。行き先だけ移るので、下書きの時刻を後から直せる。移した先にすでに別の本文があるときは警告が出る（保存すると置き換わる）
- 編集欄が空のまま日付・時刻を変えたときは、その時刻の本文をそのまま開く
- 保存は **⌘S**（Ctrl+S）。削除は二度押し
- 写真はドラッグ＆ドロップか貼り付けで置ける。R2 に上がり、`![](https://img.example.com/img/2026-08-30-14-59-13.png)` が本文に入る。JPEG と PNG だけ（[写真の置き場](#写真の置き場)を参照）
- 未保存のまま一覧の別の記事を開こうとすると一度止まる。もう一度押すと開く
- **同期** — `npm run deploy` と同じ。ビルドして Cloudflare に上げる。`deploy` の出力は走っている途中から画面の上に出る（失敗したときは赤いまま残る）。未保存の変更があるときは一度止まる。もう一度押すとそのまま同期するので、下書きを含めたいなら先に保存する

`npm run new` と同じファイルを読み書きするだけなので、コマンドラインとブラウザのどちらで書いてもいい。

確認サーバは同じネットワークの他の機械からも見えるが、書く画面はこの機械（loopback）からしか開けない。
同期ボタンは `content/` → `site/` を見ているときだけ出る。`npm run ref` の確認サーバには出ない。

### 日ページから書く

`npm run dev` の確認サーバが返す日ページには、読んでいるその場で書くためのボタンが載っている。
スマホで思いついたことを書き留めるときと、読んでいて誤字に気付いたときのためのもので、`_write` と同じファイルを読み書きする。

- 右下の **＋** で新規。開いた瞬間の日付と時刻が見出しに入り、そのまま投稿すればサーバの時計でその分のファイル（`HH-MM.md`）に書く。同じ分にもう一度投稿すると、`npm run new` と同じく空行を挟んで後ろに足す
- 見出しの日付と時刻は押せば変えられる。触ったほうだけが書き込み先に使われ、触っていないほうはサーバの時計のまま。書き忘れた日を遡って足すときはここを変える
- 各時刻ブロックの右端の **編集** で、そのブロックの本文を開いて置き換える。**削除** は二度押し
- **写真** で端末の写真を選ぶ（iOS ではカメラも選べる）。デスクトップではドラッグ＆ドロップと貼り付けも受ける。置き先は `_write` と同じく R2
- 投稿・保存・削除のあとはページが読み直され、左下に「同期」の付いたトーストが出る。書いた直後に自動では上げず、押したときに `_write` の同期と同じことをする。同期が通るか × で閉じるまで残るので、押し忘れても次に開いたときに気付ける
- **⌘Enter** で投稿と保存、**⌘S** は保存、**Esc** で閉じる。開いているあいだは `/` と `d` の割り当ては効かない
- 幅 681px 未満では下から上がるシート、それ以上では中央のダイアログになる

このボタンとシートは `site/` には書き出さない。
確認サーバが日ページの HTML を返すときに、`content/` → `site/` を見ていて、かつ loopback からの読み込みに限り、`</body>` の直前に `scripts/edit.js` と `scripts/edit.css` を差し込んでいる。
ビルド時に分岐させないのは、条件を間違えてエディタ入りの `site/` を上げてしまう事故を避けるため。
公開されるページにはこの仕組みの痕跡がなく、`_write` と同じく loopback からしか動かない。

スマホから使うには、その端末からこの機械の loopback に届く経路がいる。
`tailscale serve` なら tailscaled が localhost 宛に繋ぎ直すので、tailnet 内の端末からそのまま使える。
Funnel で外に出す場合はこの前提が崩れるので、別途認証を足す必要がある。

### 写真の置き場

書く画面で入れた写真は `content/` には置かず、Cloudflare R2 に上げる。Static Assets はファイル数に上限（20,000）があり、写真でそれを食わないため。本文には公開 URL がそのまま入り、`build.mjs` はそれを外部画像として扱う（寸法は入れたときに測って `.cache/imagesize.json` に入れておくので、ビルドが取りに行くことはない）。

バケットの中は平たく、名前は貼った日時。

```
img/2026-08-30-14-59-13.png        ← 貼ったときのサーバの時計（YYYY-MM-DD-HH-MM-SS）
img/2026-08-30-14-59-13-k3f.png    ← 同じ秒に二枚目以降が入ったときだけ短いランダムが付く
```

日付は記事の日ではなく貼った日。記事とは切り離された、ただのタイムスタンプなので、本文の日付を後から動かしても写真は迷子にならない。参照されなくなった写真の掃除はしない（消したくなったら全 md の参照とバケットの一覧の差分を取ればよい）。

事前に一度だけ用意するもの。

- **バケット** — R2 でバケットを作り、Settings → Custom Domains で公開用のドメイン（例 `img.example.com`）を付ける。ドメインは一段のサブドメインにする（二段は無料の証明書が覆わない）
- **API トークン** — 「Workers R2 Storage:編集」の権限。[公開](#公開)のトークンに足してもよいし、別に作って `HIBI_R2_TOKEN` に入れてもよい

`.env` に書く（`.env.example` を参照）。

```sh
HIBI_R2_BUCKET=hibi                  # バケット名
HIBI_R2_URL=https://img.example.com  # 公開 URL の先頭。本文にはこれ + /img/... が入る
```

`HIBI_R2_BUCKET` が無いときは写真を置けない（本文は書ける）。写しの確認サーバで試すときは、本物とは別のバケットを `HIBI_R2_BUCKET` で指すこと。

カスタムドメインはバケットを丸ごと公開するので、このバケットには公開してよいものしか置かない。`content/` の写しは別のバケットに取る（[バックアップ](#バックアップ)）。

手で `content/` の日ディレクトリに置いた写真（`![](img/xxx.jpg)`）は今までどおり `site/` に写って動く。

## 検索

末尾に出ている二語のうちの一つが「検索」。押すか `/`（⌘K でも可）で覆いが出て、そこに打つ。

- ビルド時に全文を `/search.json` に書き出し、最初に開いたときだけ読み込んでブラウザ側で絞り込む。サーバは要らない
- 拾うのは本文・引用・箇条書き・追記・写真のキャプション・リンクカードの見出しと説明・X のポスト本文。埋め込み（iframe）の中身は持っていない
- 全角と半角、大文字と小文字、カタカナとひらがなは同じものとして扱う
- 空白で区切ると、そのすべてを含む日だけが残る
- `↑` `↓` で結果を選び、`Enter` でその日へ移る。`Esc` か覆いの外で閉じる
- 動きは `assets/search.js`、見た目は `assets/style.css` の `.search-open` と `dialog.search` 以下。ボタンは JS が動いたときだけ出るので、引けない窓がページに残ることはない

## 日付ジャンプ

末尾のもう一語が「日付」。押すか `d` で、今いる月のカレンダーが覆いとして出る。

- 記述のある日だけが押せる。無い日は薄いまま動かない。今いる日は塗りつぶす
- `‹` `›`（`←` `→` でも可）で月を繰る。記述のある月だけを辿るので、空の月は出てこない
- 開いたときの焦点は今いる日。`Tab` で記述のある日だけを辿れる（無い日は飛ばす）。`Enter` でその日へ移り、`Esc` か覆いの外で閉じる
- 上の月の見出し（`2026年8月`）はその月の一覧へのリンク
- 日の一覧はビルド時に `/days.json` へ書き出し、最初に開いたときだけ読む。全文を持つ `search.json` はカレンダーを描くには重いので分けてある
- どの月を開くかは `canonical` から決める。`/` は最新の日ページの写しでパスからは日が読めないため
- 動きは `assets/jump.js`、見た目は `assets/style.css` の `dialog.jump` 以下。検索と同じくボタンは JS が動いたときだけ出る

## 遷移

一覧（月ページ）と日ページのあいだは、押した日の日付と本文がそのまま次のページの位置へ動く。残りは交差フェード。

- 動かすのは日付（`.datelink`）・その下の時刻（`.times`）・本文（`.body`）。どれも両方のページに同じ形・同じ大きさで出るので、位置しか変わらない。同じページの中のジャンプではこれに「一覧へ」（`.back`）が加わる（月ページには無いので、そちらでは見つからない）
- 動かす相手は `assets/vt.js` が選ぶ。行き先か今のページのどちらかが日ページで、その日の記事がこのページに出ていて、かつ画面の中にあるときだけ
- 日ページから「一覧へ」で入るときは、その日の記事まで送ってから測る。一覧の先頭に着いたままだと月の下の方の日は必ず画面の外にいて動かせない。送ることで戻るボタンと同じ位置・同じ動きになる（戻るボタンのときは位置が復元されるので送らない）
- 月から月、日から日（前後の移動）や検索からの移動は交差フェードだけ
- 時刻（日付の下の `.times`）で移るときも同じ動き。月一覧から時刻で日ページへ入るのは、日付を押したときと同じ（着く位置がその時刻になるだけ）
- 日ページの中の時刻ジャンプも同じ動きに揃えてある。`assets/vt.js` が同じ名前を付けてから `document.startViewTransition` の中で `location.hash` を書き換える。日付・時刻・「一覧へ」は貼り付いていて位置が変わらないので、動くのは本文だけになる
- `prefers-reduced-motion` のときは遷移しない
- `@view-transition` は `assets/style.css` の先頭に置いてある。後ろに書くと、入っていくページが最初の描画までに読み終わらず遷移そのものが起きない。`vt.js` を `defer` で読まないのも同じ理由で、`pagereveal` への登録が間に合わなくなる
- 対応していないブラウザでは何も起きず、ふつうのページ移動になる

## URL

- `/` — 最新の日ページと同じ内容（正規 URL は日ページに向ける）
- `/2026/08/` — 月ごとの一覧
- `/2026/08/30/` — 日ページ（記事の正規 URL）
- `/2026/08/30/#10-40` — その日の 10:40 の時刻ブロック。日ページの日付の下にその日の時刻が並んでいて、押すとそこへ飛ぶ。二段組では日付と一緒に貼り付く（`.meta` が sticky）ので、読んでいるあいだ左に出たままになる。月一覧の時刻はその日ページのアンカーへ向く（日付を押したときと同じく日へ移り、押した時刻の位置に着く）
- `/feed.xml` — RSS。タイトルは日付、説明は本文の冒頭 60 文字
- `/search.json` — 検索インデックス。日付と本文だけの JSON
- `/days.json` — 日付ジャンプ用。記述のある日の一覧だけの JSON
- `/404.html` — 存在しない URL 用のページ。Cloudflare Pages や Netlify などは出力ルートの `404.html` を自動で使う。`npm run dev` の確認サーバも同じものを返す

## 設定

`site.config.json`:

- `title` — サイト名
- `baseUrl` — 公開 URL。**公開前に必ず書き換える**（canonical・OGP・RSS に使う）

## 公開

Cloudflare Workers の Static Assets に `site/` を直接アップロードする。Cloudflare 側でビルドが走らないので、無料プランの月 500 回のビルド枠を使わない。

事前に一度だけ用意するもの。

- **API トークン** — Cloudflare ダッシュボードの My Profile → API Tokens で「Workers スクリプト:編集」の権限のものを作る
- **アカウント ID** — Workers & Pages のページの右側に出ている

書く画面の **同期** ボタンと、日ページで書いたあとに出るトーストの **同期** も、押すとこれと同じことをする（`npm run dev` が動いているあいだ）。

```sh
export CLOUDFLARE_ACCOUNT_ID=...
export CLOUDFLARE_API_TOKEN=...

npm run deploy                              # ビルドしてアップロード
node scripts/deploy.mjs --dry-run           # 送る内容だけ見る（通信しない）
node scripts/deploy.mjs --workers-dev       # <name>.<subdomain>.workers.dev を有効にする
```

Worker 名は既定で `hibi`。`--name` か `HIBI_WORKER_NAME` で変えられる。事前に Cloudflare 側で作っておく必要はない。初回のデプロイでその名前の Worker ができる。

同名の Worker がすでにあり、それがこのスクリプトの作ったものでないときは、上書きせずに止まる。意図した上書きなら `--force`。

変わったファイルだけを送る。二回目以降は数秒で終わる。

独自ドメインは Cloudflare ダッシュボードの Worker の設定で Custom Domain を足す。ドメインが Cloudflare のゾーンにあれば証明書も自動で付く。`site.config.json` の `baseUrl` をそのドメインに合わせておく。

`/2026/08/30` から `/2026/08/30/` への解決と、存在しない URL への `404.html` は、デプロイ時に Worker のアセット設定（`html_handling` / `not_found_handling`）として一緒に送っているので、別途の設定ファイルは要らない。

## バックアップ

`content/` は gitignore されていて履歴がどこにもないので、同期のたびに R2 へ写しを取る（`scripts/backup.mjs`）。写真の `img/` はもう R2 にあり、`site/` は `content/` から作れるので、写しがいるのは `content/` だけ。

- 置き先は写真とは別のバケット（`.env` の `HIBI_R2_BACKUP_BUCKET`）。写真のバケットはカスタムドメインで丸ごと公開されるので、本文の写しを同じ所には置かない。こちらにはドメインを付けない
- キーは `content/` からの相対パスそのまま（`content/2026/08/30/14-59.md`）。手で置いた写真も含めて md 以外もすべて写す
- R2 の一覧が返す etag（MD5）と手元を比べて、変わったものだけ送る。二回目以降は一覧一回と差分だけ
- 手元で消したファイルは R2 から消さない。消しても戻せる場所にしておくため。上書きした前の版は残らない（R2 にバージョニングは無い）

```sh
npm run backup                            # 変わったものだけ上げる
node scripts/backup.mjs --dry-run         # 上げるはずのものを出すだけ
node scripts/backup.mjs --pull            # 逆向き。R2 を正として content/ を揃える
node scripts/backup.mjs --pull --dry-run  # 書くはずのものを出すだけ
```

`--pull` は新しい機械で `content/` を戻すためのもの。R2 にあって手元に無い、または中身が違うものを書き、手元にだけあるものには触らない。手元と R2 の両方にあって違うときは R2 の側で上書きするので、手元の版を残したければ先に `npm run backup` で上げておく。

同期（`npm run deploy`、書く画面の **同期**）は公開のあとにこれを走らせる。写しに失敗したときは公開は済んだうえで赤く終わる。`HIBI_R2_BACKUP_BUCKET` が無ければ飛ばす。

## 備考

- `.cache/linkcard.json` はリンクカードの取得結果のキャッシュ。
- `assets/` の中身はそのまま `site/assets/` に写る。ファイルを足せばそのまま公開される
- 書く画面は `scripts/editor.mjs`（読み書きの口）と `scripts/editor.html`（画面）。`--watch` のときだけ確認サーバに乗る。画面は読み込みのたびにファイルから読むので、いじって再読み込みすればそのまま反映される
- 日ページに載せるエディタは `scripts/edit.js` と `scripts/edit.css`。`assets/` に置くと `site/` に写って公開されてしまうので `scripts/` にあり、`/_write/edit.js` と `/_write/edit.css` として返す。読み書きの口は `_write` と共通で、投稿（追記）のための `POST /_write/post` だけがこちら用
- 幅 681px を境に、日付が本文の上へ移って一段組になる
- 二段組では、日ページの「一覧へ」が窓の上に貼り付く（末尾まで下りても残る）。日付と時刻の列（`.meta`）は静止しているときと同じ距離だけ下げて止めるので、貼り付いてもこの二つの間隔は変わらない（`--rail-top` と `--rail-gap`）。一段組では本文が囲いいっぱいなので、どちらも貼り付けずにふつうに流す
- 月一覧では日付が日ページへのリンク。日ページでは日付をリンクにしない
- 並びは暦順。月一覧は 1 日が上で 31 日が下、前後の移動も左が過去・右が未来。一日の中の時刻が昇順なので、その上の階層も同じ向きに揃えている。新着順にするのは `/feed.xml` と `/search.json` だけ
